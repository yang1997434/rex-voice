# 协议

## 1. 配对

- Mac：`rex-voiced pair` 生成 `id`（16 字节随机）和 `key`（32 字节随机），终端打二维码：`rexvoice://pair?relay=wss://r.maruiao.top/_voice/ws&id=<base64url>&key=<base64url>`；同时把 `{id, key}` 写 `~/Library/Application Support/rex-voice/pair.json`（0600）。
- app 扫码后把三项存 Keychain（`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`，不同步 iCloud）。
- 一次性：Mac 收到第一个成功解密的握手帧后记 `paired_at`，之后再来一个声称是新设备的握手就拒（要换手机重新 `pair`）。

## 2. 中继

- `GET /_voice/ws?role=mac|phone&id=<id>`，升级成 WebSocket。中继按 `id` 配对两端：一端连上等另一端，都在就双向透传二进制帧；任一端断，另一端收到 `present:false`、连接保持。同一 `id` 同一 role 只允许一条连接，新连顶掉旧连（旧连被关，对端不收 `present:false`）。`role` 只能是 `mac` / `phone`，`id` 只许 `[A-Za-z0-9_-]{8,64}`，否则 400 不升级；不校验 `Origin`。单帧上限 64 KiB，超了断那条连接；中继每次写有 10 s 超时，写不出去就关那一端。客户端发来的文本帧除下面「推送」两种外中继忽略。
- 中继不解密、不存。`GET /_voice/healthz` → `ok`。
- **Mac→中继文本帧 `notify`**（2026-11-02）：没有通话时，Mac 发现某个 Claude 窗格变成 `blocked`，就往中继发一个**明文文本帧** `{"t":"notify","title":"<项目> 的 Claude 在等你","body":"<问题前 100 字>","block":"block:…","options":["<选项>",…]}`（0.3.3 起带 `block` 和 `options`：屏上编号选项最多 4 条、每条截 40 字，读不到就是空数组；手机凭它们在推送上直接回答，见第 3 节 `answer`），由中继转成 APNs 推送（中继侧见下面「推送」）。因为走明文，正文只放项目名和问题前 100 字，不放全文、不放 key。同一窗格 10 分钟内最多一条；窗格离开 `blocked` 前不重复触发；Mac 没连上中继时这条直接丢、记日志。监视只在 Mac（每 5 秒查一次 Rex，`internal/tools/watch.go`），手机不轮询。
- 两端之间只走**二进制帧**（第 3 节的加密帧）；中继自己发给客户端的只有**文本帧**，内容 `{"t":"peer","present":true|false}`，对端上线 / 掉线时发给另一端，连上时也立即发一次当前状态。没有对端时收到的二进制帧直接丢。
- 保活：每端空闲时每 30 秒发一个**明文** `type 3` 帧 `[03][00000000]`（没有对端时中继丢掉，有对端时对端忽略），用来刷新 nginx `proxy_send_timeout` 并尽早发现死连接；中继→客户端方向没有保活，nginx `proxy_read_timeout 3600s` 到了会断，客户端按 1s→30s 退避重连即可（通话中双向都有音频，不会触发）。
- r.maruiao.top 的 server 块对空 UA 和 `go-http` / `curl` 等 UA 一律 403，WebSocket 客户端和健康检查都要带自定义 `User-Agent`（`rex-voiced/<版本>`、`RexVoice-iOS/<版本>`，健康检查 `curl -A rex-voice-check`）。
- 推送（APNs，Mac 不在通话时手机也能收到提醒）：客户端发给中继的文本帧只认两种，其余照旧忽略，JSON 坏的忽略并记日志，都不断连接。
  - 手机→中继 `{"t":"push_token","token":"<hex>"}`：每次连上发一次；token 只许 32–200 位十六进制，否则丢。中继按 `id` 存在**内存**里（重启即丢，手机下次连上重发），手机断开后保留，同 `id` 新 token 覆盖旧的。mac 端发的忽略。
  - Mac→中继 `{"t":"notify","title":string,"body":string,"block"?:string,"options"?:[string]}`：中继查这个 `id` 的 token，没有 token 或没配 APNs 就记日志丢弃；有就异步推一条（10 s 超时），成败只记日志、不回帖给 Mac。手机端发的忽略。
  - APNs：`POST https://api.push.apple.com/3/device/<token>`，头 `authorization: bearer <JWT>`、`apns-topic: com.maruiao.rexvoice`、`apns-push-type: alert`、`apns-priority: 10`，体 `{"aps":{"alert":{"title","body"},"sound":"default"}}`；notify 带 `block` 时体为 `{"aps":{"alert":{"title","body"},"sound":"default","category":"claude-ask","mutable-content":0},"block":"…","options":[…]}`（中继只转字段、不解密不存），手机按 `claude-ask` 类别显示五个动作：`pick1`「选 1」/`pick2`「选 2」/`pick3`「选 3」→ `answer keys:["N"]`，`reply`（文字输入「输入回复…」）→ `answer text`，`esc`「取消（Esc）」→ `answer keys:["escape"]`；五个动作都要求解锁（`authenticationRequired`），点推送本身只打开 app。JWT 用 .p8（PKCS#8 P-256）ES256 签，头 `alg/kid`、载荷 `iss`（team）+ `iat`，缓存 50 分钟换一次。非 200 时错误里带状态码和 `reason`。
  - 中继环境变量：`APNS_KEY_PATH`、`APNS_KEY_ID`、`APNS_TEAM_ID`（`KAA6GJ59XS`）三个缺一个就不推、启动 warn 一行；key 读不出也只 warn、中继照常跑；`APNS_URL` 可选，覆盖 APNs 地址（测试用）。生产放 `/etc/rex-voice/relay.env`（unit 里 `EnvironmentFile=-`），.p8 的放法见 `scripts/deploy-relay.sh` 注释。
- nginx：`location /_voice/` 反代到 `127.0.0.1:8790`，`proxy_http_version 1.1` + Upgrade 头，`proxy_read_timeout`/`proxy_send_timeout 3600s`，`proxy_buffering off`，不套 `limit_req`。

## 3. 手机 ⇄ Mac 帧（经中继）

`[1B type][4B seq big-endian][ciphertext]`

- 加密 ChaCha20-Poly1305，密钥 `HKDF-SHA256(key, salt = phoneSalt ‖ macSalt（32 字节）, info="phone->mac" | "mac->phone")`，nonce 12 字节 = 4 字节 0 + 4 字节方向(0/1) + 4 字节 seq；seq 单调递增，收到回退或重复的丢弃并断开。附加数据 = type 字节。
- **会话盐（2c 落地，11-01 定）**：长期 key 直接派生会导致每次重连 nonce 重复、旧帧可重放。每条 WebSocket 连接建立后、以及每次收到中继的 `present:true` 后，双方各发一个**明文** `type 2` 帧 `[02][00000000][16 字节随机盐]`；本连接的两个方向密钥 = `HKDF-SHA256(key, salt = phoneSalt ‖ macSalt, info = 方向)`，seq 从 1 重新计。收齐两个盐之前不发、也不收 type 0/1 帧（收到就丢）；同一连接里再收到 type 2 就重新派生（对端重连了）。测试向量相应改成带两个盐（2c 已更新）。
  - Mac 侧实现（2c，`internal/call`）：中继连上时一定会立即推一次 `peer` 状态，所以 Mac **只在收到 `present:true` 时**发盐（没有对端时发了也会被中继丢掉），且**每次 `present:true` 都换一个新盐**、清掉对端盐和密钥、要求重新 `hello`——例外：两端几乎同时连上时中继会连发两次 `present:true`（2c 实测，`peerOf` 在发通知时才查），这时若还没收到任何手机盐，就**原样重发同一个 Mac 盐**而不换，否则手机会用一个 Mac 已丢掉的盐派生（所以手机必须忽略重复的 Mac 盐）；`present:false` 同样清掉。同一个 Mac 盐下收到**已经用过的**手机盐（重复发或被重放）直接忽略、不重新派生，否则 seq 归零会让本连接的旧帧可重放；收到没见过的手机盐才重新派生。盐帧长度不是 21 字节、或 seq 字段不是 0 的，丢掉并记 warn。手机侧（第 3 步）照同样规则做：每次 `present:true` 换新盐（还没收到 Mac 盐时重发原盐、不换），重复的 Mac 盐忽略，每次重新派生后都重发 `hello`（Mac 每次重新派生都会要求重新 `hello`）。
- `type 3` 保活：明文、无载荷，见第 2 节。
- `type 0` 音频：PCM16 LE 单声道 24 kHz，每帧 20 ms（960 字节明文）。手机→Mac 是麦克风，Mac→手机 是模型输出。
- `type 1` 控制：JSON。
  - 手机→Mac：`{"t":"hello","app":"<版本>","device":"<机型>","device_id":"<app 首次启动生成的随机 UUID，存 Keychain>"}`（每次连上、盐交换完先发）、`{"t":"call.start","provider":"openai|qwen|gemini|grok","model":"…","voice":"…","api_key":"…","name":"<称呼>"}`（字段都可选；`name` 是助手对用户的称呼（2026-11-02 加，设置页填），带了就本次通话用它代替 Mac `config.json` 的 `name`，只放内存；2026-11-01 用户定「手机管 key、选双工模型」：手机把设置页里的供应商 / 模型 / 音色 / 该家的 key 随 `call.start` 发来，Mac 只放内存、本次通话用完即丢，不落盘、不进任何日志和审计；没带的字段用 Mac `config.json` 的默认，`api_key` 没带时才用 Mac 钥匙串里的兜底 key；不认识的 `provider` 回 `error` 并保持 `ended`）、`{"t":"call.end"}`、`{"t":"answer","block":"block:…","keys":["2"]}` 或 `{"t":"answer","block":"block:…","text":"<文字>"}`（不打电话回答某个 Claude 的提问，0.3.3：`keys` 走 `send_keys` 的白名单和「非 Claude 窗格只许 ctrl+c / escape」，`text` 走 `send_to_pane` 的闸门（Claude 窗格放行，shell 窗格含敏感词拒）；两种都写 audit.log，行里带 `"source":"phone"`；窗格不是 blocked 也照发，窗格不存在、键不在白名单、被闸门拒都回 `answer_result ok:false`；`keys` 非空时忽略 `text`；Mac 在 `-echo` 模式下一律 ok:false）、`{"t":"voice.preview","provider":"…","model":"…","voice":"…","api_key":"…","name":"…"}`（音色试听，2026-11-02 用户定；字段和 `call.start` 同义。Mac 起一个几秒的短会话让模型说一句「<name>你好，我是你的语音助手…」（没带 `name` 就不带称呼），音频走 type 0 帧；只在没有通话时可用，通话中回 `preview error`；试听中再来一个就停掉旧的、不发旧的 `done`；试听中来 `call.start` 先回 `preview error msg=已取消` 再开始通话；`call.end` 不影响试听；手机断开就直接关会话；整段 20 秒超时）。一次性配对靠 `device_id`：Mac 第一次收到能解密的 hello 时把它记进 `pair.json`，之后 `device_id` 不同的 hello 一律回 `error` 并断开，要换手机重新 `pair`。
  - Mac→手机：`{"t":"status","state":"connecting|listening|thinking|speaking|ended"}`（`detail` 可选，Mac 目前不发，手机按可选解）、`{"t":"transcript","who":"user|assistant","text":"…"}`、`{"t":"interrupt"}`（立即停播、清空播放队列）、`{"t":"hang_up","reason":"user|idle|error"}`、`{"t":"error","msg":"…"}`、`{"t":"ask","block":"block:…","session":"<会话标签>","project":"<项目>","msg":"<问题，≤400 字>","options":["<选项 1 原文>",…]}`（0.3.3：某个 Claude 窗格变成 blocked 时发，有没有通话都发；`options[i]` 用键 `i+1` 选，最多 6 条，Mac 读屏解析 AskUserQuestion / 计划审批 / 权限框的编号行，去掉 AskUserQuestion 末尾的「Type something.」「Chat about this」，读不到是空数组；手机每次 hello 之后 Mac 把当前仍 blocked 的全部补发一遍，所以手机在每次连上时清空旧卡片；手机没连上时直接丢、记日志；不受 notify 的 10 分钟限制）、`{"t":"ask_done","block":"…"}`（窗格离开 blocked 或窗格没了时发）、`{"t":"answer_result","block":"…","ok":true|false,"msg":"<失败原因，ok 时不带>"}`、`{"t":"preview","state":"connecting|playing|done|error","msg":"…"}`（`voice.preview` 的进度：收到请求立刻 `connecting`，第一帧试听音频前 `playing`，这句说完、音频全部发完后 `done`；任何失败 `error` 带 `msg`（不含 key），含「通话中不能试听」「已取消」「超时」和连不上供应商；模型这轮一点声音都没出也算 `error`）
  - Mac→手机（2026-11-02 加，发图发链接）：`{"t":"attach","id":<整数>,"name":"<原文件名>","mime":"image/jpeg","size":<字节数>,"chunks":<分片数>}`（`show_file`：先发这条，紧接着发全部 `type 4` 分片）、`{"t":"link","url":"http(s)://…","title":"…"}`（`show_link`；`title` 可能是空串）。
- `type 4` 附件分片（2026-11-02 加）：加密，规则同 type 0/1（同一 seq 序列、附加数据 = type 字节）。明文 `[4B id BE][4B index BE][data]`，`id` 对应 `attach` 的 `id`，`index` 从 0 起，`data` ≤ 60000 字节（加头和 tag 后仍在中继 64 KiB 上限内）；按顺序发完 `chunks` 片，拼起来就是 `size` 字节的 JPEG。

## 4. Mac ⇄ 实时语音提供方

Mac 侧把提供方抽成一个接口 `internal/voice`（`voice.go`）：`voice.Dial(ctx, voice.Config{Provider, Model, Voice, Key, Instructions, Tools, Call, TextOnly, Transcribe, Logger, Handlers, UsageLog, Version, Extra}) (voice.Session, error)` 按 `Provider` 分发到各家在 `init` 里 `voice.Register` 的实现；`Model` / `Voice` 空时取 `voice.Defaults(p)`（openai `gpt-realtime-2.1` / `marin`，qwen `qwen-audio-3.1-realtime-plus` / `longanqian`（用户 11-01 定），gemini `gemini-3.8-live` / `Kore`、grok `grok-voice-3.0` / `Ara`）；不认识的 `Provider` 返回 `voice.ErrUnknownProvider`，登记了默认值但还没实现的返回「还没实现」，没 key 直接报错、不拨号；`Extra` 放各家自己的选项（openai 的 `url`、`keep_tool_outputs`）。`voice.Session` 有 `AppendAudio / SendText / Cancel / SetMuted / Close / Done / Age / MaxAge / RecentTurns`；`voice.Handlers` 是 `AudioDelta(pcm) / TextDelta / AssistantText / UserText / SpeechStarted / ResponseDone(voice.Usage) / TurnDone / Error`；工具调用不走事件，提供方内部调 `Config.Call(ctx, name, args)` 拿结果。各家不一样的都关在提供方里：打断后截断（OpenAI 的 `truncate`）和丢掉被打断那条的迟到音频、工具事件格式、裁剪工具项。会话层（`internal/call`）只认这个接口：`provider / model / voice / api_key` 按 `call.start` > `config.json` > `voice.Defaults` 合并（`config.json` 的 `model`、`voice` 只在供应商和它的 `provider` 相同时才用），`api_key` 没带时用 Mac 钥匙串里该家的兜底 key（服务 `rex-voice`、账户 = 供应商名）；手机停发真实帧 ≥ 200 ms 时调 `SetMuted(true)`、再来真实帧调 `SetMuted(false)`（Gemini 发 `audioStreamEnd`，OpenAI / Qwen / Grok 是空操作）；会话活到 `MaxAge()` 前 5 分钟时轮换（0 = 不轮换）。音频统一走 PCM16 24 kHz；提供方要别的采样率就在提供方内部重采样（`voice.Down24to16`：24k→16k，先低通再抽取），手机和会话层不知道。已定要接：OpenAI Realtime（§4.1）、阿里 Qwen-Omni Realtime（§4.2）、Google Gemini Live（§4.3）、xAI Grok Voice（§4.4）；豆包 2026-11-01 用户定去掉。

### 4.1 OpenAI Realtime（WebSocket）

- `wss://api.openai.com/v1/realtime?model=<model>`，头 `Authorization: Bearer <key>`、`User-Agent: rex-voiced/<version>`。连上先发 `session.update`，等到 `session.updated` 才算接通（10 秒没等到报错）。实现在 `internal/voice/openai`。
- `session.update`：`type: realtime`、`instructions`、`tools`、`tool_choice: auto`（没有工具时两项都不发），再按模式二选一：
  - 语音：`audio.input.format {type:"audio/pcm", rate:24000}`（只支持 24k）、`audio.input.turn_detection {type:"semantic_vad", interrupt_response:true}`、`audio.input.noise_reduction {type:"near_field"}`、开转写时加 `audio.input.transcription {model:"gpt-4o-mini-transcribe", language:"zh"}`、`audio.output.voice`（默认 `"marin"`；输出格式不设，用默认 PCM16 24k）。
  - 文字（`rex-voiced chat`）：`output_modalities: ["text"]`，不带 `audio` 块。
- 送音频：`input_audio_buffer.append {audio: base64}`；收音频：`response.output_audio.delta`（base64 PCM16 24k）。每轮回复定稿：语音模式取 `response.output_audio_transcript.done`，文字模式把 `response.output_text.delta` 攒到 `response.done`。
- 打断：收到 `input_audio_buffer.speech_started` → 给手机发 `interrupt`，并发 `conversation.item.truncate {item_id, content_index:0, audio_end_ms}`（WebSocket 模式服务端不会自动截断，`audio_end_ms` = 已经送给手机播放的毫秒数减去手机侧缓冲，先按已发送量算）。
- 工具：`response.output_item.done` 里 `item.type == "function_call"`（带 `id`、`call_id`、`name`、`arguments`），按 `response_id` 攒到这轮的 `response.done`，然后并行执行（每个 20 秒超时，超时的 output 是 `{"error":"工具超时"}`，照样送回），全部 `conversation.item.create {type:"function_call_output", id, call_id, output}` 送完再发**一次** `response.create`。用户插话导致的 `conversation_already_has_active_response` 是良性的，只记 debug。
- 省钱：一个 `response.done` 里没有工具调用、也没有工具批次还在跑，就算答完；这时把这条回答链上所有 `function_call` 和 `function_call_output` 条目用 `conversation.item.delete {item_id}` 删掉（服务端回 `conversation.item.deleted`，11-01 真跑确认）。`function_call` 的 id 取 `response.output_item.done` 的 `item.id`；`function_call_output` 的 id 由 Mac 自己在 create 时指定（`rv_out_<n>`），不靠回包——GA 版服务端回的是 `conversation.item.added` / `conversation.item.done`，没有 `conversation.item.created`。delete 带 `event_id: rv_del_<n>`，回来的 `error` 若 `event_id` 是这个前缀就忽略（删不存在的 item）。`KeepToolOutputs` 可关掉裁剪做 A/B。副作用（11-01 实测）：删掉后模型下一问要重新调 `list_panes`。会话上限 60 分钟，55 分钟时新建会话并把最近 5 轮文字当 `instructions` 附带过去（`Session.Age()` / `RecentTurns(n)`，由会话层做）。
- 用量：每个 `response.done` 的 `usage`（`input_tokens`、`output_tokens`、`input_token_details.{cached_tokens,audio_tokens,text_tokens,cached_tokens_details}`、`output_token_details.{audio_tokens,text_tokens}`）按 `internal/voice/openai/prices.go` 的单价折算（cached 按输入价的 1/10），一行 JSON `{time, model, input, cached, cached_audio, audio_in, text_in, output, audio_out, text_out, usd}` 写进 `~/Library/Logs/rex-voice/usage.log`；不在单价表里的模型 `usd:0` 并带 `unpriced:true`。

### 4.2 阿里 Qwen-Omni Realtime（WebSocket）

- 端点：默认旧端点 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=<model>`（11-01 实测北京 key 能用）；`Extra.workspace` 有值时改走 `wss://<workspace>.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime`，`Extra.url` 整体覆盖。头同 4.1。连上发 `session.update`，等 `session.updated`（10 秒），之前来的 `error` 算拨号失败。实现在 `internal/voice/qwen`。
- 地域与 audio-3.1（11-01 实测）：key 绑地域，北京 key 在国际站 401、国际 key 在北京 401；不带 `Extra.url/workspace/region` 时先连北京、失败换 `wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime`，`Extra.region = cn|intl` 可直指。国际站有 `qwen-audio-3.1-realtime-plus/flash`：它不认 `semantic_vad`（只有 `server_vad / smart_turn / smart_turn_v2`，代码按模型名选 `smart_turn_v2`）、音色表另一套（`longanqian`… 和 `*_v3.1`，3.8 的 `Tina` 被拒，默认改 `longanqian`）、没在答时发 `response.cancel` 回 error「Conversation has no active response」（只在有回答时才取消）；文字 / 工具 / 语音三条真测都过。
- `session.update`：`instructions`、`audio.input.format {type:"pcm", sample_rate:16000}`（3.8 只收 16k）、`audio.output.voice`（**文字模式也必须带**，服务端默认的 `Chelsie` 3.8 不认，会回 error 并断开）、`tools`（OpenAI 扁平格式原样发，实测接受、模型能调；不用套 `function:{}`）；文字模式加 `modalities:["text"]`；语音模式加 `turn_detection {type:"semantic_vad"}`，`input_audio_transcription` 开转写时 `{model:"qwen3-asr-flash-realtime"}`、不开时发 `null`（否则服务端默认开 `gummy-realtime-v1`）。
- 上行：24k PCM16 经 `voice.Downsampler` 转 16k 再 `input_audio_buffer.append`。文字轮用 `conversation.item.create {type:"message", role:"user", content:[{type:"input_text"}]}` + `response.create`——文档没列 message 类型，实测可用。
- 下行：`response.audio.delta`（24k）→ `AudioDelta`；`response.audio_transcript.done` → `AssistantText`；`response.text.delta` / `.done` → `TextDelta` / `AssistantText`；`conversation.item.input_audio_transcription.completed` → `UserText`；`response.function_call_arguments.done`（带 `response_id`、`call_id`、`name`、`arguments`）按 `response_id` 攒到 `response.done` 后照 4.1 批处理（结果 `function_call_output`，最后一次 `response.create`）。
- 打断：`input_audio_buffer.speech_started` → `SpeechStarted` + `response.cancel`，并丢掉被打断那条回复（按 `response.created` 的 id）的迟到音频。没有 `truncate` / `delete`，不裁剪工具项；被取消的回复 `response.done.status = "cancelled"`，`audio_transcript.done` 仍给全文。实测空闲时 `cancel` 不回 error，只在 `response.created` 之前取消回 `Cannot cancel response before response.created`，这类含 cancel 的 error 吞掉；11-02 实测工具结果后的 `response.create` 撞上用户在说话会回 `Cannot create response while user is speaking`（按 `while user is speaking` 不分大小写匹配），记 Info、不断会话，记下要重发，收到 `input_audio_buffer.speech_stopped` 时补发一次 `response.create`，期间先来了 `response.created`（服务端自己起了回答）就不再补发；补发若撞上服务端自己起的回答回 `already has an active response`，同样记 Info 不断；其余 `error` 报 `Handlers.Error` 并结束会话。
- 会话上限 120 分钟；`SetMuted` 空操作。
- 用量：`response.done.usage` 的 `input_tokens`、`output_tokens`、`input_tokens_details.{text_tokens,audio_tokens}`、`output_tokens_details.{text_tokens,audio_tokens}`（注意是 `tokens_details`），按 `internal/voice/qwen/prices.go` 北京价（元/百万 token：文本入 1.5、音频入 6、文本出 4.5、音频出 12，出处 https://help.aliyun.com/zh/model-studio/model-pricing ，按 7.2 折美元）写同格式 usage.log 行，`cached` 恒 0。

### 4.3 Google Gemini Live API（WebSocket）

- 端点 `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?key=<key>`（`Extra.url` 整体覆盖，照样追加 `?key=`）；key 在 URL 里，日志和错误文案只写不带 `key=` 的地址。头 `User-Agent: rex-voiced/<version>`。服务端消息是二进制帧 JSON；出错一律是关闭帧（1007 / 1008 + 原因），Mac 读出原因报 `Handlers.Error` 并结束会话。实现在 `internal/voice/gemini`。
- 第一条发 `setup`：`model: "models/<model>"`、`generationConfig {responseModalities:["AUDIO"], speechConfig.voiceConfig.prebuiltVoiceConfig.voiceName}`（默认 `Kore`；`responseModalities` 放 setup 顶层会被 1007 拒，11-01 实测）、`systemInstruction.parts[0].text`、`tools[0].functionDeclarations[] {name, description, behavior:"BLOCKING", parametersJsonSchema}`（**不能用 `parameters`**：它不认 `additionalProperties`，1007）、`realtimeInputConfig.automaticActivityDetection.silenceDurationMs: 700`、`outputAudioTranscription:{}`、开转写时 `inputAudioTranscription:{}`、`sessionResumption:{handle?}`、`contextWindowCompression.slidingWindow:{}`；等 `setupComplete`（10 秒）。文字模式发 `responseModalities:["TEXT"]`，`gemini-3.8-live` 在第一轮回 1007「response modalities (TEXT) is not supported」，所以 `rex-voiced chat` 用不了 gemini。
- 上行：24k 经 `voice.Downsampler` 转 16k，`realtimeInput.audio {data, mimeType:"audio/pcm;rate=16000"}`（24k 直送标 `rate=24000` 实测也能识别，没用）；`SetMuted(true)` 发一次 `realtimeInput.audioStreamEnd:true`、静音期间不发音频。文字轮 `clientContent {turns:[{role:"user", parts:[{text}]}], turnComplete:true}`。
- 下行：`serverContent.modelTurn.parts[].inlineData.data`（PCM16 24k）→ `AudioDelta`；`outputTranscription.text` 逐段 → `TextDelta`，攒到 `turnComplete` → `AssistantText`；`inputTranscription.text` 攒到下一个 `modelTurn` / `voiceActivity {type:"ACTIVITY_END"}` → `UserText`；`voiceActivity {type:"ACTIVITY_START"}` 或 `serverContent.interrupted` → `SpeechStarted`，被打断那条的迟到音频丢到 `turnComplete`；服务端自己停，`Cancel` 空操作。
- 工具：`toolCall.functionCalls[] {id, name, args(对象)}`（之前没有 `turnComplete`）并行执行（20 秒超时）→ 一条 `toolResponse.functionResponses[] {id, name, response:{result:<工具原字符串>}}`，不用再触发；`toolCallCancellation.ids` 取消对应执行、不回传。`turnComplete` 时没有工具批次在跑才 `TurnDone`。
- 续接：存 `sessionResumptionUpdate` 里 `resumable:true` 的 `newHandle`；收到 `goAway {timeLeft}` 立刻新开连接、setup 带 `sessionResumption.handle`，换好再关旧连接，同一个 Session 对会话层透明（换的那一下丢的音频不补）。`MaxAge` 0。
- 用量：`usageMetadata` 跟 `turnComplete` 同一条到（11-01 实测）：`promptTokenCount`、`responseTokenCount`、`thoughtsTokenCount`、`promptTokensDetails[] / responseTokensDetails[] {modality: TEXT|AUDIO, tokenCount}`；思考 token 不在 `responseTokenCount` 里、按文本出计入 `output` / `text_out`。按 `internal/voice/gemini/prices.go`（美元/百万 token：文本入 0.75、音频入 3、文本出 4.5、音频出 12）每轮写一行 usage.log，`model` 写 `gemini/<model>`，`cached` 恒 0。

### 4.4 xAI Grok Voice（WebSocket；2026-11-01 真 key 跑通文字 / 工具 / 语音，扁平 tools、不带 type 的 session.update 服务端都收）

- `wss://api.x.ai/v1/realtime?model=<model>&reasoning.effort=none`（默认 `grok-voice-3.0`；`Extra.reasoning` 改 effort，服务端默认 `high` 拖慢首包；`Extra.url` 覆盖端点），头同 4.1。连上发 `session.update` 等 `session.updated`（10 秒）。事件名同 OpenAI GA，实现在 `internal/voice/grok`（从 openai 包复制改的）。
- `session.update`：**不带** `type`、不发 `tool_choice`；`instructions`、`voice`（顶层，默认 `Ara`，不分大小写）、`tools`（扁平格式，同 4.1）；语音模式加顶层 `turn_detection {type:"server_vad", idle_timeout_ms:60000}`（不发 semantic_vad / interrupt_response / noise_reduction）、`audio.input.format` 与 `audio.output.format` 都是 `{type:"audio/pcm", rate:24000}`（24k 直通，不重采样）、开转写时 `audio.input.transcription {model:"grok-transcribe", language_hint:"zh"}`；文字模式只加 `output_modalities:["text"]`。
- 下行同 4.1，另外 `response.text.delta` 与 `response.output_text.delta` 都收（一轮里只认先到的那个名字，防止重复）；`conversation.item.input_audio_transcription.updated` 是累计全文，只存不报，`.completed` 来了以它为准报 `UserText`，没来就在 `response.created` 时把累计全文当 `UserText`（同一 item 只报一次）。
- 打断：`speech_started` → `SpeechStarted` + `conversation.item.truncate`（同 4.1），不发 `response.cancel`（server VAD 自己取消）。
- 工具：同 4.1 批处理，但这轮回复出过音频的，`response.create` 要等到它的 `response.output_audio.done`（或用户插话，最多等 10 秒）再发——xAI 说上一条音频没到齐就 create 会叠音；本地播放有没有播完不管。裁剪工具项同 4.1（`conversation.item.delete`）。会话上限 120 分钟，`SetMuted` 空操作。
- 用量：按连接时长计费（$0.08/分钟，含静音），每条 `SendText` 另加 $0.004，`function_call_output` 免费（`prices.go`）。`response.done` 只报 tokens、`usd` 记 0；`Close`（含拨号失败）时写一行 usage.log：4.1 的字段加 `seconds`，`input` / `output` 是整个会话的 token 合计，其余 0。

| `close_pane` | `block`, `scope="pane"\|"window"\|"session"`, `force?` | `{closed}` 或 `{refused}` | `rex ls` / `rex block ls` 找 sid 和窗格的 `window_id`；目标范围（pane 是它自己、window 是同 `window_id` 的窗格、session 是整个会话）里有 `program_status` 为 `working` 的且没带 `force`，返回 `{"refused":"<block> 正在 <msg>，要关请确认 force"}`。否则 pane：`rex block close -s <sid> <block>`；window：`rex window close -s <sid> <window_id>`；session：`rex session kill <sid>`（11-02 实测：block / window close 的 id 是位置参数，不收 `-b`）。关和被拒都写审计 `{tool:"close_pane", text:<scope>}`。 |
| `rename` | `target="session"\|"window"\|"pane"`, `id`, `name` | `{renamed, name}` | session：`rex session rename -- <id> <name>`（`id` 收标签或 id）；window：`id` 填该标签页里任一窗格的 block，按 `window_id` 找标签页后 `rex window rename -s <sid> -- <window_id> <name>`；pane：`rex block rename -s <sid> -- <block> <name>`。带 `--` 防名字以 `-` 开头。`name` 去首尾空白后为空报错。只改 Rex 里的名字；Claude 自己的会话名用 `send_to_pane` 发 `/rename <名>`。 |
| `send_keys` | `block`, `keys[]` | `{sent}` | 白名单 `enter escape up down left right tab shift+tab ctrl+c` 和单字符 `0`–`9`（不区分大小写），有一个不在就整条报错不发；`rex send-key -s <sid> -b <bid> <keys…>`；写审计 `{tool:"send_keys", text:<空格连起来的键>}`。用途：回答 Claude 的 AskUserQuestion / 计划审批 / `/model` `/effort` 选择框。11-02 在真 Claude Code（v2.1.316）里实测：数字键直接选中对应编号（不用 enter），`down`+`enter` 选下一项，`escape` 取消提问框，`shift+tab` 切权限模式；`y` / `n` 在提问框里没反应，已从白名单删。 |
| `hang_up` | `reason?` | `{ok}` | 由会话层用 `tools.HangUpDef(run)` 注册（第 2b 步）：只记下「要挂」，等模型这轮说完（`TurnDone`）再给手机发 `hang_up`、关会话，见第 6 节。提示词：听到「挂断吧 / 先这样 / 拜拜 / 不聊了」先说一句告别再调。 |
| `show_file` | `path` | `{sent, size, chunks}` | `internal/tools/show.go` 校验 + 转换，发送由会话层注册：展开 `~`，只收 `.png/.jpg/.jpeg/.heic/.webp` 且 ≤ 20 MB；`sips -Z 1280 -s format jpeg <src> --out <临时文件>`（用完删），结果 > 2 MB 报错；没有通话报「没有通话」；按第 3 节发 `attach` + `type 4` 分片。 |
| `show_link` | `url`, `title?` | `{sent}` | 只收 http / https（要有主机名）；没有通话报「没有通话」；发 `link` 控制帧。 |

`block` 和 `session` 参数容错解析（11-02 Grok 实测会传 `2-0`、去掉 `block:` 前缀的 id、拼错的会话名）：所有带 `block` 的工具（`read_pane` / `read_claude` / `send_to_pane` / `send_keys` / `close_pane` / `rename` 的 window·pane）共用 `resolveBlock`——原样 → 加 `block:` 前缀 → 去前缀后作为某个真实 id 的唯一前缀（≥ 8 字符），都不中返回「没有这个窗格: <输入>。现有窗格：<会话标签>/<窗格标签> = <完整 id>，…」（最多 12 个）；收 `session` 的（`open_pane`、`rename` 的 session）共用 `resolveSession`——标签或 id 原样 → 不分大小写 → 去掉空格和连字符后相等 → 唯一子串 → 编辑距离 ≤ 2 的唯一者，某一步命中多个就报候选，都不中列出全部会话标签；解析后一律用会话 id 调 rex，`open_pane` 返回的 `session` 是会话标签。

出错一律返回 `{"error":"…"}`（不超过 300 字），不让会话层报错：未知工具、参数不是 JSON 对象或带未定义字段、外部命令失败（取它 stderr）、工具内部 panic 都走这条，模型能看到原因。

提示词（实验版，继续打磨）：中文、口语、像电话汇报；要调工具先说「我看一下」；问项目时把属于它的窗格全看一遍；Claude 结论用 `read_claude`，屏幕现状才用 `read_pane`；汇报一句话说结论（带卡点），命令、路径、代码、链接、日志一律不念，用户要细节再展开（`read_claude` 带 `verbose`）；附称呼（`call.start` 的 `name`，没带用 `config.json` 的 `name`）和 `config.json` 里 `project_aliases`（项目说明），以及每次 `call.start` 和会话轮换时现生成的标签表（在跑的 Claude 目录名 + Rex 会话名），见 `internal/voice/prompt.go` `Build`。

## 6. 静音与挂断

- app：能量门限（RMS 低于阈值的 20 ms 帧不发，阈值真机调），有声后再多发 300 ms（15 帧）防吞字尾；不发 `idle` 状态帧（Mac 自己按收帧计时）。
- Mac 补静音（11-01 真跑发现：手机停发后服务端 VAD 判不出用户说完）：通话中每 20 ms 检查，距上一个真实音频帧超过 200 ms（小于这个间隔算中继抖动，不插零）且不超过 5 s 时，往 OpenAI 追加 960 字节全零 PCM；超过 5 s 停止补（长静音不计费）。静音计时只看真实帧。
- Mac：60 秒没收到音频 → 让模型说一句「还在吗？没事我先挂了」；90 秒 → `hang_up reason=idle`。
- 挂断延后（2026-11-02）：模型调 `hang_up` 时 Mac 不立刻挂，等这轮回答结束（`TurnDone`，Grok 要等到 `output_audio.done`）、把剩下不足一帧的音频也发完，再发 `hang_up reason=user`；8 秒内没等到 `TurnDone` 也挂，免得道别被截断或一直挂不掉。
